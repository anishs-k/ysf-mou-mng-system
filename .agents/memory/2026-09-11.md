## Environment gotchas discovered the hard way

- **Turborepo must be launched through `npm run <task>`.** Running
  `./node_modules/.bin/turbo` directly fails with "Unable to find package manager
  binary". Turbo needs the npm-launched context.
- **Turborepo 2.x runs in strict env mode.** `DATABASE_URL` and `TEST_DATABASE_URL`
  are stripped from child processes unless declared in `turbo.json`. They are now in
  `globalEnv`.
- **Node 24 is required** (root `engines`), and Node 24's npm is 11.13.0 while the
  root manifest pins `packageManager: npm@11.16.0`. Turbo tolerates the mismatch once
  launched via npm.
- **`node --test` runs test files in parallel by default**, which corrupts a shared
  database. `test:integration` uses `--test-concurrency=1`.
- **`typescript-eslint` (8.70.0) caps TypeScript at `<6.1.0`**, so it cannot be used
  in `@mou/api`, which is on TypeScript 7. `@mou/api` therefore has no lint script.
- Both `@mou/api` and `@mou/domain` need `allowImportingTsExtensions` +
  `rewriteRelativeImportExtensions`, because Node's type stripping requires explicit
  `.ts` extensions in source while the build must emit `.js`.
- `docker compose` (plugin form) is unavailable on this machine; use the standalone
  `docker-compose` CLI. Postgres runs on host port **5434** (5432 and 5433 are taken).

## Verified against PostgreSQL

`end_date` is accepted as a **generated column** — the immutability risk flagged in
SPEC-01 §6.1 did not materialise, so no `BEFORE INSERT OR UPDATE` trigger fallback is
needed. `drizzle-kit generate` reports "No schema changes", confirming the schema and
the committed migrations are in sync.

## Deviations from SPEC-01 that should be reviewed

1. **Migrations are 0000 + 0001, not the six in §9.1.** drizzle-kit generates from one
   schema file, so the whole schema lands in one migration; only `business_today()` is
   a custom migration. The §5.14 indexes live in the Drizzle schema (single source of
   truth) and therefore in `0000`, not in a `functions_indexes` migration.
2. **Two extra files beyond §9's list**: `src/api/src/db/company-code-repository.ts`
   (AC14 needs the §6.3 statement) and `src/api/src/db/test-harness.ts`.
3. `0001_business_today.sql` uses `CREATE OR REPLACE FUNCTION` so it is re-appliable.
4. `tests/e2e/src/workspace.test.ts` now resolves `@mou/web` through its manifest
   instead of importing `PACKAGE_NAME`, because `@mou/web` is a Vite app with no
   library entry point.
5. The `user` table keeps the spec's reserved name; it must always be quoted in raw
   SQL.
