## Playwright gotchas

- **The proxy was the big one.** This sandbox sets `HTTP_PROXY` / `HTTPS_PROXY` to
  `http://127.0.0.1:61781` with **no `NO_PROXY`**. Playwright honours those for its
  own web-server readiness probe as well as for the browser, so the probe for
  `http://localhost:5173` was sent to the proxy, never reached the dev server, and
  the run stalled until the 120s `webServer` timeout — with no browser process ever
  appearing. `curl http://127.0.0.1:5173/` returning **502** is the tell.
  Fixed by `bypassProxyForLocalhost()` in `tests/e2e/playwright.config.ts`, which
  appends `localhost,127.0.0.1,::1` to `NO_PROXY`. It is set in the config rather
  than only in the shell **because turborepo filters environment variables before
  Playwright starts**. `environment.sh` and `turbo.json` `globalEnv` also carry it.
  Symptom to remember: a `test:ui` run that hangs for many minutes with no browser
  in `tasklist` and no error output.
- The base URL must be `localhost`, not `127.0.0.1`. The API's CORS allow-list and
  the session cookie are scoped to `localhost`; mixing the spellings silently breaks
  credentials.
- `tests/e2e` overrides `moduleResolution` to `bundler`. The base config's NodeNext
  demands explicit extensions on relative imports, which Playwright does not resolve
  the same way.
- Playwright's `testDir` only collects `*.spec.ts`, so `accounts.ts` and `sign-in.ts`
  can live alongside the specs as helpers.
- `test-results/`, `playwright-report/` and `blob-report/` are gitignored.
- Playwright leaves orphaned dev servers behind on Windows if a run is killed
  mid-flight. Check ports 3000 and 5173 before re-running; `reuseExistingServer`
  will happily reuse a zombie.
- `global-setup.ts` must delete **all** `login_attempt` rows, not only the fixture
  accounts, because tests like "unknown username" use hard-coded identifiers
  (`no-such-user`) that can accumulate lockouts across debugging runs and would
  otherwise make the test expect a 401 generic error but receive a 429 lockout.

- **A real bug found and fixed before the isolated test run even needed to
  catch it**: the summary query's `LEFT JOIN company_plant` and
  `LEFT JOIN scoped_mou` are both independently keyed on `c.id`, which is a
  Cartesian product per company — a company with *P* plants and *M* MOUs
  produces *P×M* joined rows. `COUNT(DISTINCT cp.id)` was already safe, but
  the MOU-derived columns used plain `COUNT(sm.id)`, silently doubling a
  two-plant company's MOU count. Caught by deliberately writing a
  two-plant-company regression test (no acceptance-criteria test happens to
  use a multi-plant company), fixed with `COUNT(DISTINCT sm.id)`
  throughout. **Lesson worth generalizing**: two independent one-to-many
  `LEFT JOIN`s from the same parent row always need `DISTINCT` on whichever
  side's count you actually want.

  days left" fixture when N is large** — it always uses a 1-month tenure,
  so an MOU it creates ending 45 days out hasn't started yet (derives NEW,
  not ACTIVE): a 1-month agreement ending in 45 days would have to start 15
  days from now. Wrote a local test-only helper (6-month tenure, same
  generated-column-inversion technique) for AC6's "already active, 45 days
  remaining" case. General lesson for future specs reusing this helper: it
  targets "N days until expiry," not "N days remaining on an
