## Migration gotcha worth remembering

`drizzle-kit generate` **prompts interactively** (`promptColumnsConflicts`)
whenever a table has both an added *and* a removed column, and it hard-fails
without a TTY. The guard is `process.stdin.isTTY`, so piping input does not
help. There is no `--force`/`--yes` flag in v0.31.10.

Workaround used: split into two migrations so no single generate sees both.
- `0006_spec16_additions` — all additions (kept `company.generated_code` and
  `company_code_counter.zone_id` temporarily).
- `0007_spec16_code_move` — all removals + the counter PK re-key.

`--name` does not pass through `npm run db:generate` (the root script delegates
to a workspace script), so migrations come out auto-named
(`0006_windy_outlaw_kid`); rename the `.sql` file **and** the `tag` in
`drizzle/meta/_journal.json` together. Confirmed `No schema changes, nothing to
migrate` afterwards.

### Migration bug found and fixed (important)

The generated migrations **only worked on an empty database**. The dev DB has
30 companies / 33 MOUs / 220 payroll_item rows and `db:migrate` crashed three
times. The integration suite never caught it because the test DB is always
built from scratch. Fixes, hand-written into the generated files:

- `0006_spec16_additions.sql`: `company.sector` and `mou.generated_code` are
  added as nullable, backfilled, then tightened to NOT NULL. Sector → `OTHER`.
  MOU codes rebuilt as `MOU-<SCHEME>-<YYYY>-<NNNN>` via
  `row_number() OVER (PARTITION BY scheme, EXTRACT(YEAR FROM mou_start_date))`
  (cannot copy `company.generated_code` — 3 companies hold 2 MOUs, and 0007
  drops the column anyway). 15 of the 22 old payroll keys have no counterpart

  `initcap(replace(item_key,'_',' '))` as the label rather than deleted.
- `0007_spec16_code_move.sql`: `DELETE FROM company_code_counter` before
  re-keying (old values are meaningless under the new PK and block
  `SET NOT NULL`), then the counter is seeded from the backfilled MOUs so the

a *populated* database, not just `drizzle-kit generate` + CI on an empty one.
